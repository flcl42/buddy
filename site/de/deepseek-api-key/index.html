Vor dem Start

  • Verwende ein Konto, das du kontrollierst und wiederherstellen kannst.
  • Halte eine unterstützte Zahlungsmethode bereit, falls kein Aktionsguthaben verfügbar ist.
  • Halte den neuen Schlüssel geheim; behandle ihn wie ein Passwort.
  • Nutze lokales Qwen für Text, der dein Gerät niemals verlassen darf.

2

API-Schlüssel erstellen und kopieren

  1. Öffne API keys in der DeepSeek Platform.
  2. Erstelle einen neuen Schlüssel und gib ihm einen erkennbaren Namen wie Chitchat Buddy.
  3. Kopiere den vollständigen Schlüssel sofort und halte ihn geheim, bis er in Buddy gespeichert ist. DeepSeek-Schlüssel beginnen normalerweise mit sk-.
Gib den Schlüssel niemals weiter. Nach den Open-Platform-Bedingungen bist du für Nutzung und Kosten eines durchgesickerten Schlüssels verantwortlich. Füge ihn nicht in Screenshots, Feedback, Quellcode oder browserseitige Web-Apps ein.

3

Guthaben und Abrechnung prüfen

Ein erstellter Schlüssel garantiert kein nutzbares API-Guthaben. Öffne Top up, lade nur einen für dich angemessenen Betrag auf und kontrolliere den Verbrauch regelmäßig.

  • 401 Authentication Fails bedeutet meist, dass der Schlüssel falsch oder unvollständig ist.
  • 402 Insufficient Balance bedeutet, dass das API-Konto Guthaben benötigt.
  • Die aktuelle DeepSeek-FAQ nennt PayPal, Bankkarte, Alipay und WeChat Pay; die Verfügbarkeit kann abweichen.

4

Schlüssel mit Chitchat Buddy verbinden

Bei der Ersteinrichtung: Wähle unter Chatbot platform DeepSeek · my API key, füge den Schlüssel ein und drücke Download and set up.

Nach der Einrichtung: Öffne die Buddy-Einstellungen, suche Cloud provider keys, füge den Schlüssel in DeepSeek API key ein und drücke Save provided keys. Wähle danach DeepSeek unter AI language provider und drücke Use selected.

So schützt Buddy den Schlüssel: Er wird im sicheren Benutzer-Anmeldedatenspeicher des Betriebssystems abgelegt. Buddy leert das sichtbare Feld nach dem Speichern und zeigt einen vorhandenen Schlüssel nie wieder an.
5

Bietet DeepSeek Zero Data Retention?

Es gibt keine veröffentlichte Zusicherung, dass die direkte DeepSeek-API Daten überhaupt nicht speichert. Behandle sowohl deinen eigenen Schlüssel als auch Buddys begrenzten DeepSeek-Zugang als Cloud-Verarbeitung ohne ZDR.

  • Die Open-Platform-Bedingungen versprechen kein ZDR. Sie beschreiben, wie API-Eingaben zu Ausgaben verarbeitet werden, und verlangen von App-Entwicklern die Offenlegung ihrer Verarbeitung personenbezogener Daten.
  • Die aktuelle allgemeine Datenschutzrichtlinie sagt ausdrücklich, dass sie die Verarbeitungsregeln für Endnutzer in nachgelagerten Anwendungen nicht abdeckt. Für die von ihr erfassten Dienste gibt DeepSeek an, Prompts und Eingaben erfassen, Informationen zur Verbesserung oder zum Training verwenden und personenbezogene Daten nach Bedarf aufbewahren zu können.
  • Die Richtlinie bietet einen Widerspruch gegen die Nutzung zum Modelltraining. Das begrenzt einen Verwendungszweck, ist aber nicht dasselbe wie keine Speicherung.
  • DeepSeek gibt an, erfasste personenbezogene Daten in der Volksrepublik China zu verarbeiten und zu speichern.
  • Die API-Dokumentation beschreibt außerdem automatisches Kontext-Caching auf Festplatten. Eine zustandslose API-Anfrage bedeutet daher nicht „nichts wird gespeichert“.

Buddys begrenztes Gateway speichert Schlüssel-Hashes und numerische Nutzungswerte statt Dialogtext. Der angeforderte Text erreicht dennoch DeepSeek; das Gateway macht die externe API daher nicht zu ZDR.

Praktische Regel: Sende keine Passwörter, privaten Schlüssel, Gesundheitsdaten, vertraulichen Besprechungsdetails oder Texte, die du nicht weitergeben darfst. Wähle lokales Qwen, wenn der Text auf deinem Computer bleiben muss.
